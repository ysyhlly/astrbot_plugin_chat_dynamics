# 群间 · Chat Dynamics

AstrBot 群聊互动插件。合并连续碎发、追踪话题，使用 AstrBot 原生 Jev / System One 模型决定是否接话，再由普通聊天模型和 AstrBot 主 Agent 生成回复。

**v1.17.0，要求 AstrBot 4.29.4 或以上（小于 5）。** 本版新增可切换的 LLM 对象与讨论归属判断，默认保持规则＋原生重排序方案。安装前保留原配置和数据备份；伙伴插件按需接入，基础聊天不要求全部安装。

设置页新增“插件联动与设置归属”，显示伙伴版本、接口状态和当前启用功能的依赖。它只检查状态，伙伴的数据和配置仍在各自插件中维护。完整职责表、升级顺序与扩展约定见 [插件联动说明](docs/integrations.md)。兼容补丁与主插件安装包分开提供，按基准版本检查后使用。

从 rc.42 起，默认由规则识别“在对谁说”，不再推断具体回复哪句话。多人讨论的歧义由独立的原生 Rerank 服务辅助处理，同一个人可以参与不同讨论。请在“话题识别与归属”中选择“讨论归属重排序模型 ID”；未配置时保留未知，不自动使用聊天模型补猜。详细行为和回退方式见 [规则与讨论归属](docs/rule-topic-routing.md)。

rc.43 修正了单条消息被过早建成主题的问题：低分先保留待定，有后续引用或语义支持才形成讨论。同时恢复独立的“话题归纳模型”，批量概括已形成的讨论；它与 rerank 可以同时使用。

## 切换归属判断

在设置页“话题识别与归属”中保持“使用新版对话归属链路”开启：

- `对象与讨论判断模式 = rerank`：沿用规则判断回复谁，原生 Rerank 判断讨论归属。
- `对象与讨论判断模式 = llm`：用普通聊天模型合并判断隐含回复对象和讨论归属；设置“归属判断 LLM”和超时。模型留空沿用回复模型，再留空则使用当前会话聊天模型。可随时切回，两个模型配置分别保留。
- 真实 @、引用优先。模型只选当前会话提供的对象和讨论，不推断具体回复哪句；超时、无效或低置信结果保留已有规则结果，不补调 Jev 或 Rerank。
- 普通消息的 LLM 判断在参与决策前执行，默认最多等待 3 秒，会增加延迟。真实 @、引用不等待这一步；后台讨论归属和话题命名保持独立。关闭“启用讨论归属辅助”后不调用归属 LLM。
- 话题名称继续使用独立“话题归纳模型”，不能修改归属。关闭新版链路仍恢复旧 Jev 路径，此时模式选择不生效。私聊保持原直接回复路径。

## 配置

rc.44 的调用优化会合并符合边界条件的同回合碎发、跳过无有效内容的 rerank、复用相同请求并对失败短暂退避；规则路由不再等待 embedding。回复准备增加按阶段的服务耗时和同回合版本化读取复用。`overview.call_optimizations` 可检查实际调用、缓存、合并及耗时，不改变正式回复或话题归纳模型。

1. 安装 Chat Dynamics 后，在 AstrBot 模型服务中选择内置的“Jev / System One”或“OpenCode Zen · Jev”服务，填写地址和密钥，获取列表并添加模型。
2. 打开“插件参数配置”，刷新模型列表，选择决策模型。
3. 选择生效群聊，核对排除名单与回复模型，保存并立即应用。默认不处理任何群聊。

地址、密钥和模型 ID 统一由 AstrBot 模型服务维护。回复模型留空时使用 AstrBot 默认聊天模型。Jev 只用于结构化决策。

v1.15.0 已内置原 `astrbot_plugin_systemone_catalog` 的模型列表、服务模板、连接测试和决策调用。升级保留 `systemone_catalog` 类型及现有服务 / 模型 ID，无需重建模型或重填密钥。旧独立插件可以停用，Chat Dynamics 单独安装即可使用这些功能。

模型列表使用 `GET /v1/models`，决策使用 `POST /v1/systemone`；支持服务前缀、自定义路径、请求头和环境变量密钥。OpenCode Zen 列表只显示 `jev-` 型号，已有旧列表路径会兼容纠正。每次决策重新解析当前模型，切换模型或卸载后的旧请求结果会丢弃。

## 页面与参与控制

- 群聊动态控制台：会话、冷却与重置；“参与与分寸”集中展示群聊状态并调整全局参与程度。
- 插件参数配置：社交、作息、主动配额、媒体、记忆、隐私和消息节奏等详细参数。
- 记忆小本：查看和维护已有的群聊记忆。
- 场景回放：查看决策过程，保留人工标注及导出，跳转控制台调整参与设置。
- 决策模型：查看 Jev 连接、调用次数、失败次数和最近请求耗时；按需导出历史样本。

参与程度对所有生效群聊应用，排除名单优先。观察模式不发送插件回复；普通群聊和引用 / 昵称唤醒仍调用决策模型。

选择“活跃”后，机器人会寻找切入点参与大家正在聊的公开话题，分享看法、经验、建议或接梗；话题不必与机器人有关，也不需要 @ 或等到冷场。两位群友轮流发言或引用彼此的消息不会单独阻止接话，明确只问某位群友、私人话题、冲突和停止要求仍会保持距离。每会话每分钟最多主动加入 4 次，实际是否接话由 Jev 判断，仍受开口概率、冷却和作息控制。

在“插件参数配置 → 全部”中，可编辑“决策模型”下的 **参与决策提示词**（`decision_prompt`）和“回复正文”下的 **回复提示词**（`reply_prompt`）。支持多行文本，各最多 4000 字符；保存后立即用于后续回合，留空恢复默认。前者调整什么时候参与、偏好哪些话题，后者调整接话方式和语气；原有人设仍由 AstrBot 人格管理维护。

回复长度默认优先 `brief` / `normal`；简单列表、少量步骤和技术问题不会单独触发 `detailed`，只有明确要求详细展开或短答会遗漏必要信息时才选详细回复。`normal` 默认用 1~2 句或最多两项的短列表，普通群聊 `detailed` 要求整轮正文不超过 120 字，先给结论，只保留必要解释，发送前检查并压缩超长表达。仅要求详解不放宽 120 字限制；明确完整代码、长文或指定更长篇幅的请求可按需展开。长度通过提示词控制，正文按生成结果完整发送。旧默认回复提示词自动升级，自定义提示词保留，可在上述“回复提示词”中调整长度偏好。

话题归属交给 **同一次 Jev 请求**判断：继续现有话题就归入该话题；确定为新讨论时建立新话题，不确定时保留本地判断。普通 LLM 仅为新增或首次确认的无标签话题生成简短标签，已有标签会加入后续 Jev 的匹配上下文并持续复用。标签按群默认累计 **30 秒**后合并生成，不阻塞即时回复；无新话题时不调用普通模型。可在“插件参数配置 → 全部 → 话题识别与归属”调整 **新话题标签累计间隔**（`topic_batch_interval`，5–300 秒）。

话题超过 **一小时无人继续讨论**后移出活跃列表并归档，不再供 Jev 匹配，也不自动重新打开；匹配成功的人类消息刷新这一个话题的活跃时间，机器人回复不会续期。短上下文窗口或消息淘汰不会提前移除已缓存的标签。每群最多保留 80 个活跃话题，超额时归档较早的话题；Jev 看到全部活跃标签，最相关、最近的 8 个话题额外附带简短讨论证据。归档沿用现有 24 小时、最多 32 项的保留限制。

场景回放每 5 秒自动更新已形成的话题和小标题，归档标签显示在历史话题中；累计期间先展示话题及归纳状态，连续聊天不会取消同一话题的标题。查看详情或编辑标注时暂停自动更新。话题小标题默认显示，消息正文仍默认隐藏，可在“面板隐私”中分别控制。标签生成使用话题标签模型，留空沿用回复模型；生成超时默认 10 秒，一批最多为 8 个话题生成标签，每个话题最多带 3 条消息。观察模式也能生成标签。

普通消息先经过最多 0.25 秒的短暂聚合，再由同一次 Jev 请求判断“是否说完”和“是否接话”。完整句子、问题或短回应不因缺少句号、末尾逗号而固定延长等待；决定接话后，正文生成完成即发送。Jev 确认未说完时保留原输入，收到新消息才合并重判，期间不反复请求模型。补充输入从首条消息计时，默认等待最多 60 秒，可在“消息合并”中调整 `pending_input_timeout`（1–300 秒）；超时、停止、重置和卸载会清除等待。快速碎发的一批合并仍使用原有上限，旧版默认组合自动迁移，自定义窗口保留。话题向量与标签在后台更新，平台明确 @ 继续直接进入回复。

续聊按话题和参与者查找已发送回复，机器人回答其他成员后，原对话仍可接续。Jev 同时获得冻结的最近回复、待回答问题、用户补充及其来源。日常续聊窗口为 2 分钟；话题独立确认且仍在处理任务时可恢复 15 分钟内的同一对话，情绪支持为 5 分钟；收尾或明确指向其他人的消息不借用续聊资格。回复 Agent 继续使用 AstrBot 原生历史及记忆钩子。

回复中的空行会划分独立消息，即使正文较短也按自然段依次发送；段内单次换行不拆分，动作描写与紧接着的台词保留在同一条。默认最多发送 10 段，超出的段落合并到最后一条，不丢弃正文。在“消息节奏”中调整 `max_fragments`，范围为 1~10，设为 1 则整段发送；`inter_burst_interval` 默认 1.2 秒。普通回复、戳一戳及原生回复均支持分段，代码、列表、公式、链接和媒体消息保持完整。中途停止只取消尚未发送的内容，历史保留实际送达的段落。

## 唤醒规则（v1.14.1）

- 平台消息中明确 @机器人：必须回应，直接进入回复，不等待 Jev，也不受普通参与概率、冷却或作息静默挡住。生成失败、空结果或超时后补一条简短回应；已发送过内容则不重复补发。
- 引用机器人消息但没有 @，或叫机器人昵称 / 唤醒名：交给 Jev 判断实际接话对象，分别使用配置的引用 / 名称门槛，同时需要达到动作置信度要求且选择非 ignore 动作。引用本身不会把“不回复”改成“回复”。仅谈论机器人、明确对其他人说话或对象不明时继续旁听；有真实已发送对话依据的实质续聊继续按续聊规则处理。
- 引用群友消息：保持普通群聊判断；如果同时 @机器人，则按 @必回处理。

上述规则用于已启用并接管的群聊。观察模式不发送，指令由指令处理器处理；用户停止、会话重置与卸载会取消旧请求。媒体限制继续控制附件读取；需要回应时可以仅发文字确认，不自动放开附件权限。

`/dynamics_stop` 会取消该成员尚未完成的 Agent 与工具调用，群组继续处理其他成员的请求。戳一戳也遵循成员停止及回复总超时。普通回复和戳一戳共用按 Provider 计算的并发预算，默认最多 4 个调用；排队时间计入调用超时。已确认的续聊取得名额后正常交给 Jev 判断。宿主历史保留工具与媒体来源，只保存实际送达的回复正文。

## 独立交互边界联动

Chat Dynamics 可通过公开插件注册表联动 `astrbot_plugin_autonomous_blocking`。该服务按同一平台实例与机器人账号隔离规则；`silence` 仍可进入 Chat Dynamics 的群聊观察与 DAG，`shield` 会在进入角色管线前拦截，并过滤可归属的历史与召回材料。来源不完整的旧宿主历史会在有效 shield 期间从模型请求中暂时移除，原记录不会删除。

`autonomous_blocking_required` 默认关闭以保持旧配置行为。部署并启用边界插件后，应将该项设为 `true`；服务缺失、未就绪或无法确认当前机器人身份时，Chat Dynamics 会停止角色请求和回复，插件管理员配置命令仍可用于关闭该项。有效 silence/shield 优先于普通 @ 回复规则。第三方插件绕过公开边界发送的消息不在 Chat Dynamics 的发送保证内；没有可信收件人的主动群消息会安全跳过。

回退时先把 Chat Dynamics 的 `autonomous_blocking_required` 设为 `false` 并确认配置已生效，再禁用或卸载独立边界插件。这样可以先恢复 Chat Dynamics 的旧路径，再移除策略服务。

## 成员身份

群成员按平台账号区分：QQ 群上下文同时提供昵称和 QQ 号，同名成员分开识别，改名后仍归属于原账号。真实 @ 与引用保留对应账号；纯文本里的“@昵称”不能单独确定身份。新保存的回复历史也保留发言者归属，避免后续对话把同名成员混为一人。

## 超时与发送保护

普通群聊及引用 / 昵称唤醒每回合只进行一次 Jev 决策请求，不自动重试；Jev 超时、不可用或对象不明确时继续旁听。@机器人不调用 Jev，回复生成总等待受回复模型超时约束。配置切换、用户撤销、会话重置和过期结果检查继续保护发送。决策超时与回复正文超时分别配置。

v1.16.0-rc.38 统一当前消息的回复对象与放行判断：可靠的“其他对象”结论、当前片段的成员对象判断和明确只 @其他成员的消息，不会被正向 action/join 覆盖。背景消息的对象不否定当前邀请，真实 @机器人、对机器人的明确称呼和公开群问题保留各自路径。第三方续聊复用同次请求的逐消息对象问题，比较继续和群友聊、转向机器人、公开发问和对象不明，不增加额外模型请求。

已确认对象是机器人、话已说完且目的明确时，如果模型只是在“简短回应”和“回复”之间分散概率，可使用完整动作分布作一次简短回应；不会把可靠 ignore、其他对象、边界或未完成输入改为回复，也不会因此额外调用模型。

场景回放也展示“未归话题消息”，不会为它们制造话题。每轮保留闭集模型动作、对象、置信度、平台 @ / 引用、采用规则和发送结果；记录按既有全局快照预算保留，重启后仍可查看。隐藏消息内容时一并隐藏这些记录中的身份标识，不保存模型推理正文。

社交、作息或媒体限制会把已确认的唤醒改为简短文字回应。平台发送失败会记录失败；生成兜底同样需要平台服务能成功发送。人格桥接不可用时采用内部降级路径，并在控制台提示。

## v1.14.0 精简

已移除 AI 标注审批、旧学生模型训练与上线管理、教师采集、Kev / AgentJev / Laya 决策兼容、独立 Jev 地址与密钥配置、后台氛围模型调用、自动发布策略应用，以及独立的“今日读空气”和“分寸台”页面。

Jev 下无效的 WTS 权重不再暴露为用户设置；内部降级判断使用固定默认值。

历史数据库、记忆和人工标注保留。决策历史只通过只读连接按需分页导出，默认隐藏聊天内容，不迁移、采集或清理数据库。旧配置中的训练与发布策略字段不会重新启动这些功能。

## 运行要求

AstrBot 4.29.4–4.x；正常的人格与主 Agent 管理器。安装包仅含源文件，不包含配置、密钥、数据库或群聊内容。

## 开发验证

安装 `requirements-dev.txt` 和 AstrBot 4.29.4 后，运行 `python scripts/run_checks.py backend`。SDK 集成测试单独运行 `python -m pytest integration -q`；不要与单元测试混在同一进程。未安装 LivingMemory 时，一项真实伙伴工具用例会标为可选跳过；可在源码 checkout 中运行 `python scripts/prepare_companion_fixture.py --destination data/plugins/astrbot_plugin_livingmemory`，准备固定基线并应用兼容补丁的隔离源码夹具。CI 会准备此夹具并强制执行全部 SDK 用例，不依赖在线插件。此脚本不加载插件，不覆盖不同的已有目录。

浏览器检查先安装 Playwright Chromium，再运行 `python scripts/run_checks.py browser`。`python scripts/check_release.py` 核对发布文件和页面资源，`python scripts/build_release.py` 生成运行安装包；`python scripts/build_compat_release.py` 单独生成兼容包。发布门槛以这些维护中的检查为准，早期兼容路径测试仍保留为历史参考。

CI 使用这份当前回归清单，覆盖内置模型服务、唤醒、决策、取消、配置、持久化与当前页面，并单独运行真实 AstrBot SDK 的主 Agent、原生消息和停止指令集成测试。全源码 lint 与基础模块类型检查继续保留。旧训练、旧后端和旧模型决策模式的历史测试保留在仓库，不代表 v1.15 仍支持这些功能；本版本不沿用包含退役功能的旧覆盖率门槛。
