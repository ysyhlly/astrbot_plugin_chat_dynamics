# 群间 · Chat Dynamics

让 AstrBot 跟上群聊节奏：合并连续消息、识别对话对象和话题，判断何时接话，再由主 Agent 生成回复。

**v1.18.1 · 需要 AstrBot ≥ 4.29.4、< 5。**

## 安装与开始使用

1. 在插件市场通过本仓库安装，或下载 [Release](https://github.com/ysyhlly/astrbot_plugin_chat_dynamics/releases/latest) 中的主插件 ZIP。
2. 在 AstrBot「模型服务」添加需要的聊天模型；使用 Jev 时另添加抉择模型。
3. 打开插件唯一的 **“群间 · Chat Dynamics”** 页面，进入“参数配置”，选择生效群聊、参与决策方式和回复模型，然后保存。

默认不接管任何群。升级会保留现有配置，不会自动切换决策方式。地址和密钥统一在 AstrBot 模型服务中管理。

## 模型怎么选

| 用途 | 设置与作用 |
| --- | --- |
| 是否接话 | **参与决策方式**：`jev`（默认）使用 Jev／原生抉择；`llm` 使用普通聊天模型，不要求配置 Jev。判断动作、状态、回复长度及是否等待补充输入。 |
| 回复谁、属于哪个讨论 | **对象与讨论判断模式**：`rerank`（默认）使用规则＋原生重排序；`llm` 使用普通聊天模型辅助判断。真实 @、引用优先，不猜具体回复哪句话。 |
| 话题名称 | **话题归纳模型**：为已形成的讨论生成标题，不修改消息归属。 |
| 回复正文 | **回复模型**：通过 AstrBot 主 Agent 生成回复，沿用人格、工具和已授权的上下文。 |

两类判断可以独立切换，原模型选择分别保留。普通 LLM 决策和归属模型留空时沿用回复模型，再留空使用当前会话聊天模型。原生 Rerank 需单独选择，不能填写聊天模型。

LLM 参与决策默认超时 6 秒，归属判断默认 3 秒；参与决策还受总时限约束。失败时保守处理，不串行补调另一个后端。模型自报分数不等于实测正确率，LLM 模式也不保证更快。

## 常用操作

AstrBot 插件管理的原生“配置”窗口默认显示常用项；打开“显示高级配置”可调整超时、阈值和缓存。所选模型方式和功能开关会控制相关参数的显示，隐藏项的原值保留。

统一页面内部提供 **控制台、参数配置、决策模型、记忆小本、场景回放** 五个功能区。

- 在控制台调整参与程度、冷却或重置会话；观察模式只记录，不发送插件回复。
- 在配置页调整参与提示词、回复提示词、私聊、消息节奏和隐私设置。
- 用 `/dynamics` 查看和控制状态；`/dynamics_stop` 取消当前成员尚未完成的回复与工具调用。
- 查看决策页的实际后端、调用次数和耗时，或在回放中检查接话原因与送达结果。

真实 @ 保留快速回复路径；引用和昵称仍需通过参与判断。成员停止、屏蔽、隐私和来源校验始终生效。面板默认隐藏消息正文。
