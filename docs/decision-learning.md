# 决策学习操作指南

决策学习将 LLM 的语义判断作为教师标签，用于训练 Laya。机器人回复正文仍由 AstrBot 主 Agent 生成；冷却、权限、发送结果和会话隔离继续由代码控制。它与原有 Dynamics Learning 阈值学习是独立功能。

教师答案是硬标签，0/1 是标签编码，不表示教师有 100% 置信度。学生输出的概率需在独立校准集上校准后用于接管判断；不能把教师的确定标签当作可比较的置信度。

当前题目版本为 `2`，教师提示版本为 `zh-rubric-v2`。相关度、问题价值、专业性、沉默倾向、参与强度分别使用五档中文评分标准，教师与学生收到相同题面。各维度独立评分，不以“机器人应该沉默”代替其它维度的零分；不强制均匀分布。

决策学习另收集五档 `reply_length` 与主要收件人 `recipient_choice`；原有三档 `length`、收件人路由和 `TurnDecision` 契约继续保留。AgentJev 离线训练的数据筛选、整轮 Choice 转换与当前样本门槛见 [AgentJev 群聊决策训练入口](agentjev-training.md)。

人设模式的决策学习快照另含结构化 `environment`（E，`schema_version=1`）：当前轮是否 @ 机器人、是否回复机器人、距上次机器人发言的秒数、决策前连续的机器人消息数、近五分钟机器人消息数、活跃群友数与群消息数，以及深度冷却剩余秒数。均由插件运行时读取，不从聊天文本猜测；无可靠来源或保留的消息窗口不完整时写 `null`。快照与逐题标签一起匿名化保存，教师在当轮及后台补标时使用同一份 E。旧样本缺少 E，应作为无 E 的历史样本区分。

常规人设 LLM 决策（`decision_mode=persona_model`、`decision_backend=model`）也把同一结构化 E 随会话状态交给模型，供其判断本轮是否开口。模型会同时考虑人设、对话和参与策略；E 中的 `null` 表示未知，群活跃度本身不构成必须插话的理由。`decision_learning_mode` 开启时仍沿用原有教师/学生路径；当前 AgentJev `decision.v1` 在线学生尚不能消费独立 E。

教师缺少必需证据时可仅对该题返回 `null`。该题不作为训练负例，进入 `review` 队列并标记 `insufficient_evidence`，其它有效标签仍保留。空人设卡有明确默认档位，按默认档处理。在线执行继续采用已有保守回退。每条教师标签记录实际提示版本，历史未记录版本的标签显示为 `legacy-v1`。

面板创建训练作业默认只导出当前题目版本；历史样本仍可普通导出和对比。手工提交同一任务混合题目版本的数据集会在加载 GPU 前被拒绝，避免末条版本覆盖前面的版本。模型产物记录教师提示版本来源计数。

## 启用与观察

在插件参数中设置 `decision_learning_mode`：`off` 保持原行为；`collect` 采集教师标签；`shadow` 让教师执行、学生旁路比较；`active` 仅让通过验收的学生任务接管。新安装默认 `off`。

`decision_learning_sessions` 填写完整会话 UMO；明确选择采集所有生效群时可填 `*`，采集仍检查插件生效／排除规则，且只处理当前已建立的会话。只有配置范围内的会话保留训练样本；不要只填写群号。默认保留 30 天，可用 `decision_learning_retention_days` 调整。后台教师补标每小时预算由 `decision_learning_labels_per_hour` 控制，设为 0 暂停补标。自动补标最多 3 路并行，共享每小时预算并遵守提供商的前台容量预留；空队列轮询间隔为 1 秒，连续失败按 1、2、4、8、15 秒退避（上限 15 秒）。使用 `*` 时，重启后的旧会话在重新出现后恢复后台补标。

学生不确定时回退 LLM，再回退本地规则。`decision_learning_jev_fallback` 默认关闭；开启后在学生与 LLM 之间尝试 Jev。接管后用 `decision_learning_sample_rate` 保留随机教师比较，默认 5%。

随机比较按完整请求抽样，该请求缺失的全部教师标签一起进入补标队列。训练允许部分标签；晋升评估只使用已补齐全部问题的请求，避免用单题延迟代替整轮延迟。

“Jev 对照最近样本”仅在点击时调用已配置的 Jev，对最近最多 20 条教师样本作比较，总预算 20 秒；结果不会自动作为训练标签，也不会更改当前决策后端。

Docker Compose 内使用 `laya_base_url=http://laya-server:8900`，并在 `laya_internal_hosts` 中加入精确主机名 `laya-server`。训练和推理服务的部署、权重下载及 GPU 检查见 [Laya 部署指南](laya-deployment.md)。

## 面板工作流

从插件侧栏进入“决策学习”。页面通过 AstrBot Plugin Page bridge 调用宿主认证的 Web API，不使用独立浏览器令牌，也不把非空用户名当成管理员权限。主机认证与插件作用域校验由 AstrBot 的 `register_web_api` 调度器提供。

1. 查看各任务样本数与运行模式。缺少指标时显示 `—`；不会把缺测当作零错误。学生任务占比按实际执行来源统计，最近请求 p95 只反映当前诊断窗口，不能替代目标主机的完整验收报告。
2. 检查教师样本量。分组划分、去重、校准与测试由训练流程完成；同一会话默认以至少 30 分钟无采集样本的间隔划分连续对话段，同一段不会跨集合，跨段近重复输入仍合并。按时间保留较新的组用于校准和测试，因此单个群也能在积累多个独立对话段后训练。不要手动随机拆分连续对话。导出样本功能可用于离线审查。
3. 在训练作业表单填写新模型标识和训练轮数。提交时自动导出当前 SQLite 教师样本到 `DECISION_DATASETS_DIR` 共享卷。模型标识必须唯一，训练不覆盖既有模型。作业由后台 worker 执行，可查询和取消。
4. 训练后填写候选模型标识并“查看评估”。评估结果来自训练 worker 生成的不可变报告；该按钮不会重新运行训练。未通过门槛的任务继续由教师执行。
5. 通过验收后显式晋升，从 10% 会话开始接管。“下一阶段”核验本阶段已观察 24 小时且新增至少 500 条有效比较，再推进至 50%、100%；不足则拒绝推进。如发现问题可回滚上一稳定版本。晋升不意味着全部任务已达到可接管标准。

若管理操作不可用，确认 AstrBot 和 Laya 服务设置相同的 `LAYA_ADMIN_TOKEN`。令牌通过容器环境提供，不放入插件配置或页面。服务不可达时页面显示错误，不能将其视为训练完成或没有作业。

“样本质量复核”显示教师提示词版本及证据不足等标记。可用“对比新旧教师提示词”对少量样本发起比较；默认每批 6 条，页面最多等待 120 秒，结果显示在操作结果区且仅包含脱敏汇总。标签改变不等于质量改善，仍需人工核验，不能凭改变数量选择提示词。

## 人工复核标签

是否开口、回复目标及收件人等关键任务需要独立人工复核，不能仅凭教师与学生一致就晋升。先导出样本，阅读其中的 `state` 和 `candidates`，再制作 UTF-8 JSONL 复核文件，每行包含原样本 `id` 和 `human_label`：

```json
{"id":"原样本标识","human_label":true}
```

`noul` 标签使用布尔值，`choice` 使用候选键字符串，`score` 使用从 0 开始的整数等级。人工标签不得照抄教师答案代替独立判断。通过以下命令导入，数据库路径指向插件实际使用的 `decision-learning.sqlite3`：

```bash
python scripts/decision_dataset.py --database /path/to/decision-learning.sqlite3 review reviewed.jsonl
```

导入会校验候选值，将复核结果和时间保存在样本元数据中，不覆盖原教师标签，也不改变在线决策。导入后重新导出数据并创建新的训练作业，让最终独立测试集中的复核标签进入人类对照评估；既有模型的不可变评估报告不会被修改。

从 `decision_learning_sessions` 移除会话后，后台队列不再领取该会话的待标注样本。已有样本仍遵循保留期；需要立即清理时使用会话删除操作。

## 管理 API

验收使用更保守的接管错误门槛：除错误率不超过 5% 外，95% Wilson 置信区间上界也必须不超过 5%。同一请求内多个候选不会当作多个独立请求；任一已接管候选错误，该请求记为错误。请求级证据不足时继续由教师执行，旧报告缺少这些指标时不能直接晋升。

回复目标另有完整请求级集合评估，报告整组完全匹配率、误选数、漏选数及回应动作没有目标的组合错误。目标任务晋升至少需要 500 个完整目标请求，集合错误和接管集合错误的置信上界均需过关。仍须满足原有人工复核要求；置信区间不代表已消除跨请求的对话相关性。

补标队列会优先处理明确点名、多目标、长上下文及学生预测落在缺样本类别的请求。学生预测仅作为采样线索，不会写成教师标签。优先抽样以完整请求为单位，保留原随机抽样；同会话相同当前文本与题型组合 15 分钟内只获得一次优先权。缺失教师标签的原有补标仍继续，每五次成功领取任务按最早入队顺序处理一次，防止普通样本长期等待。优先级和领取计数持久保存，标注仍受原有每小时预算限制。

质量复核区显示“是否开口与动作矛盾”“回应动作没有目标”“关键任务师生分歧”等标记。标记仅用于审查，不改变教师标签、在线决策或自动认定教师错误；导出的样本 `metadata.quality_flags` 和 `sampling_reasons` 保留审查线索。目标标签未补齐时不判定缺目标。已有人工复核导入命令可用于记录独立判断。

对已有样本补跑审查：`python scripts/decision_dataset.py --database /path/to/decision-learning.sqlite3 audit --limit 200`。输出只包含已审查和有标记的请求数；面板标记数按样本行统计，同一请求多题可能重复计数，不可当作独立错误次数。

学习页同时显示学生请求状态、有效师生配对数、各任务类别数量和原始采集缺口。`teacher_finished_first` 表示教师已完成，仍未完成的旁路请求已取消，不等待学生拖延回复；该次缺失预测不算学生答错。HTTP 错误、超时、版本不匹配及无效答案分别计数。

Shadow 模式在共享输入准备后并发调用教师与学生，始终采用教师答案。原始采集缺口按 500 条及每个固定类别 50 条展示，仅用于采集规划；独立测试集的数量、质量及晋升资格仍以评估报告为准。话题候选索引随请求变化，不按索引计算固定类别缺口。

以下路径均位于插件的 `/astrbot_plugin_chat_dynamics/learning/` 下，通过宿主后台认证访问；请求和响应沿用插件的 `{status, ok, data, error}` 包装。

| 路径 | 方法 | 请求 |
| --- | --- | --- |
| `stats` | GET | 无 |
| `jobs/create` | POST | `model_id`、可选 `epochs`；数据集自动导出 |
| `jobs/status` | POST | 可选 `job_id`；省略列出作业 |
| `jobs/cancel` | POST | `job_id` |
| `models/evaluate` | POST | `model_id` |
| `models/promote` | POST | `model_id` |
| `models/rollback` | POST | 空对象 |
| `models/rollout` | POST | 空对象；根据真实观察数据推进 |
| `models/compare_teacher` | POST | `limit: 6`；新旧教师提示词脱敏对比 |
| `samples/export` | POST | 可选 `session_key`、`limit`、`cursor` |
| `samples/delete` | POST | 必填 `session_key` |

导出每次最多 1000 条，若响应有 `next_cursor`，用该值继续请求下一页。删除只针对指定会话，并清理关联数据集；页面会在执行前显示确认。模型晋升和回滚也需要显式操作。

所有管理请求受大小和频率限制，关停期间拒绝操作。训练服务异常不会向页面泄露内部异常文本或密钥。插件面板的接口单元测试不等同于目标 Windows Docker 主机上的 GPU、真实 SDK 或端到端性能验证。

### 快照完整性与旧数据隔离

学习专用快照保留逐条消息正文、时间、回复关系和 @ 对象，并提供 `target_candidates`、`routing_semantics.recipient_candidates` 显式映射。普通回复提示词继续使用原有展示预算。历史消息不能晚于本轮触发消息；未知正文标记为缺失，不从合并正文或后续消息猜补。

`/prepare` 只移除完整的可选历史条目，输出完整 JSON；候选正文、当前消息和被引用的回复上下文放不下时明确拒绝。旧的完整双 JSON 对象快照可无损合并，残缺 JSON 不再被接受。标注与学生仍共享 `state`；`metadata.source_state` 另外保存本轮完整匿名化原始输入，`snapshot_version=1` 标记新采集格式。`tokenizer_prepared=false` 表示使用完整源输入交给教师，尚未适配小模型预算，不可把原始标签直接移植到另一份被截短的输入上。

先审计已有数据，再按需要隔离：

```sh
python scripts/decision_dataset.py --database /path/to/decision-learning.sqlite3 audit-snapshots
python scripts/decision_dataset.py --database /path/to/decision-learning.sqlite3 audit-snapshots --quarantine
```

隔离只标记 `invalid_snapshot` 并停止补标队列，不删除原文、不修改已有教师标签。训练导出、切分和训练入口都会检查快照完整性；后台教师也拒绝损坏输入。旧数据丢失的正文不能靠解析残片恢复，应从完整原始记录重新构建并重新标注。旧导出文件应重新审计，不能仅凭此前的“clean”文件名判定可训练。
