# reasoning-store 契约

`core/reasoning_store.py` 的数据契约。**它与 `decision_trace` 是两份契约,不可混用。**

> 这份存储**含文本**。这一点写在最前面,因为它正是 `decision_trace` 明确不含的东西。

## 1. 为什么是两份

`decision_trace` 是**有界事实**记录,不含任何自由文本 —— 对话正文、`response_goal`、人设文本、模型推理,一概不进
(`core/persona_trace` 的模块注释、`tests/test_trace_free_text_boundary.py`)。学习层把它当「无正文」读,这条一旦破了,
所有依赖它的消费者都会在不知情的情况下开始处理聊天内容。

但推理链仍然要收集:**只有能解释判断的文字,才能教会判断**;纯枚举只能教分类。

所以文本走这里,自己一份键前缀、自己一份契约,并且明写「含文本」。分开不是为了整洁,而是为了让有界记录对
所有消费者继续成立。

## 2. 键

| 键 | 内容 |
|---|---|
| `chat_dynamics_reasoning_salt_v1` | 假名用的安装期盐(32 字节,hex) |
| `chat_dynamics_reasoning_v1_<sha256(session)>` | 该会话的推理记录列表 |

## 3. 记录字段

| 字段 | 说明 |
|---|---|
| `store_schema_version` | 当前 `1` |
| `session_hash` / `msg_ids` / `ts` | 归属与时间,`msg_ids` 是判定针对的消息 ID |
| `decision` | **只引用不复制**有界那半(`action`/`state`/`length`/`reason_code`/`reason_category`),防止两份记录各自漂移 |
| `rationale` | 模型自述的推理链 |
| `response_goal` | 模型写的回复目标 |
| `alternatives[]` | `{action, why_rejected}` —— 被否掉的选项与理由 |
| `scrubbed` | 恒为 `true`;**为假的记录不得使用** |

**不包含**:对话正文、人设文本、任何 `MessageSnapshot.text`。`core.scrub.collect_identifiers` 也刻意不把正文当标识符收集。

## 4. 去标识化

入库前一律经过 `core.scrub`:

1. 先在**提示词**层禁止:要求模型引用 `message_id`,禁止复述名字、ID、消息原文。**这是主控制**,比任何事后擦除都强 —— 模型不引用,就没有可擦的。
2. 事后擦除是纵深防御:`URL`/`EMAIL` 整体替换,引号内引文整体替换为 `<QUOTE>`,已知实体替换为 `<ENT_xxxxxx>`,连续 5 位以上数字替换为 `<ID>`。

**假名必须跨记录稳定**,否则同一实体在不同样本里是不同 token,关联被切断。用**带盐 HMAC** 而不是裸 hash ——
QQ 号只有 10 位,裸 hash 可在秒级穷举反查。**转盐即切断可关联性**,这也是留存期限的执行方式。

> ⚠️ **这是尽力降低,不是匿名化。** 规则擦除抓不到绕过替换的昵称、异体字写法的人名、以及不点名却可定位到人的表述。
> 请把擦除后的记录当作「风险较低」,而不是「安全」。

## 5. 生命周期与开关

- **默认关闭。** 关闭的含义是「不收集推理」,不是「收集了但藏起来」;开启是一次需要留痕的动作。
- 写入**尽力而为**:存储不可用时判定不受影响。*记录推理绝不能反过来代价推理本身。*
- 无推理可留(三个字段全空)则不产生记录,**不补造**。
- 追加是读-改-写,存在丢失窗口。丢一条是训练数据的缺口,不是正确性问题 —— 与整份存储的不对称性一致。

## 6. 谁能用

只走 Laya 那条**受限链路**(明文 HTTP 仅限回环/RFC1918/链路本地/CGNAT)。这份存储含聊天衍生文本,
因此与 `decision_trace` 同等对待传输约束。
