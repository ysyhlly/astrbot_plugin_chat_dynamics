# 持续行为反馈

这组能力沿用 Dynamic Life State 的 SQLite 状态，由 Chat Dynamics 将同一份当前成员状态提供给决策模型和原生回复 Agent。需要启用现有 narrative 联动及目标会话；没有启用该链路的私聊直通模式不会获得这些跨轮状态。

## 用户纠正

`humanlike.corrections` 保存成员、类别、适用话题、原话依据、后续应采取的做法和状态。类别包括理解、长短、建议、玩笑及称呼。记录按会话、角色实例和成员隔离，重启不清空。

- “以后回复简短一点”“不要总是给我建议”等严格匹配的直接反馈在事件入库时保存，不依赖模型可用性。
- 更复杂的纠正由现有叙事模型从本人向机器人表达的原话中提取；本轮明确纠正本身仍直接参与回复，不等待后台长期状态才生效。
- 无 @ 的续聊中，当前回合语义确认“纠正上一轮”、接收人为机器人且已允许回应时，会把这一依据附加到生活事件副本，不改写平台实际 @ 或引用事实。
- 理解纠正必须指定话题。一般表达偏好只有明确长期要求才使用空话题；本次任务的事实不会被当成其他话题的条件。
- 后续模型收到的是具体行为调整，不是固定道歉文案。当前反馈优先于旧记忆中的同项理解。成员主张不因此成为已验证的外部事实。
- 本人可明确修改或撤销；普通寒暄、时间流逝、其他成员发言和模型自己的道歉不会撤销记录。旧时间的输入不能覆盖新记录。

## 表达轻重

回复请求增加 `attention_plan`，使用已通过置信度和当前回合身份校验的语义结果：纠正先修复、倾诉先倾听、求助聚焦问题、简单回应简短收尾。原有发言许可、停止规则、长度约束和工具权限继续生效。

## 情绪与兴趣

情绪可记录具体话题、原话原因和 `settled` 状态。余波继续按时间衰减；来源不能重复刷新，澄清后可结束，对其他成员不投射。

`humanlike.interests` 保存稳定 ID、话题、当前进展、下一步和最近四次有来源的推进。讨论、成功执行和角色虚构日常分别标记为 `discussion`、`execution`、`fiction`；讨论过不等于实际读完、玩过或执行完成。下一步不构成主动发送授权。会话兴趣的参与成员不可因更新而改变。

## 验证边界

自动测试覆盖入库、跨重启、后续决策/回复投影、成员及会话隔离、纠正撤销、陈旧事件、情绪衰减/结束、兴趣推进和执行回执验证。模型能否在自然聊天中正确提取所有措辞并表达得自然，需要上线后的真实会话验收；测试不替代这一步。
