# v1.3.12 补充审查核实与修复

本次在已有锁外路由与画像缓存改动上继续修复，统一随 v1.4.0 发布。

| 项目 | 核实结果与处理 |
| --- | --- |
| 回复没有插件总超时 | 确认。普通生成 60 秒、工具 Agent 120 秒；人设桥接绕过 LLMAdapter 的路径也有完整处理 watchdog，取消传播并释放队列名额。 |
| thread/topic 混用 | 确认。统一 `node_topic_id`，routing 存在时以其 topic_id 为准（空值也有效），仅没有 routing 的旧节点兼容顶层镜像。引用与未成题续聊继续保留独立证据。 |
| 阈值重复映射 | 上轮已拆配置，本轮用 `ThreadRouter.configure_topics` 集中构造与热更新规则。保留旧配置语义供已有安装兼容。 |
| 配置属性重复赋值 | 确认。单一显式属性清单，特殊 set/list 转换和组件 configure 仍独立处理。 |
| takeover 查询副作用 | 确认。谓词只读已应用配置；入口显式 refresh，未变化时不解析、不重配置，支持原地修改列表。 |
| 每 30 秒无条件持久化 | 确认。用变更版本跳过空闲期序列化与 KV 调用，保存期间的新变更不会丢失，失败继续保持待保存，重置/退出保留强制保存。 |
| 数据存源码目录 | 确认。使用宿主稳定数据目录，保留旧文件、不覆盖目标。旧无 UMO 身份的记录不做猜测归属。 |
| safe_umo 碰撞 | 确认。追加 128-bit 哈希并在数据中校验 UMO，区分替换字符、空值和截断前缀相同的会话。 |
| Persona 构造失败 | 确认。启动降级规则模式，控制台可见原因；保留原配置和主动保存前的可用性验证。 |
| 取消 finally 等状态锁 | 确认等待存在；不能据此断言必然死锁。改为不含 await 的任务所有权检查与清理，并在队列为空时原子关闭所有权。 |
| 裸 pytest 收集旧副本 | 已复现 9 个收集错误。新增 pytest.ini 限定 tests/integration。 |
| 静态检查 | 新增 ASYNC 检查及五个基础模块的 mypy 门禁；不进行数百处与本次修复无关的注解改写或批量忽略。 |
| escapeHtml 空值 | 已统一为 String(value ?? "")。 |
| 同消息两次强地址判断 | 已复用入口判定结果。 |
| 根 i18n | 当前 SDK 运行时读取 .astrbot-plugin/i18n，根资源仍有测试及发布约束。本次保留，不按“仓库无引用”删除。 |
| Web wrappers | 无引用的结论不准确；单元测试与真实 SDK smoke 仍调用这些兼容入口。保留。 |
| register 弃用 | 保留 AstrBot 4.16 兼容，不因较新 SDK 的弃用警告直接移除。 |
| 页面资源副本 | 既有宿主分发与资源同步机制，本轮未改。 |

复验使用 `.venv` 中实际 AstrBot 4.27.5，包含 Provider 挂起、后继请求、任务取消、未成题引用、配置刷新、存储碰撞与数据复制场景。合成测试用于证明这些边界行为，不能代替真实群聊质量指标。

## 最终验证

- Python 3.12.3 / AstrBot 4.27.5，`CHAT_DYNAMICS_REQUIRE_REAL_SDK=1 python -m pytest`：1429 passed（包含 integration）。
- 总覆盖率 91.65%，90% 总门槛和各关键模块门槛通过。
- 最后补强的任务所有权回归另跑 4 passed；人设降级浏览器回归通过。
- Ruff（含 ASYNC）、mypy 五个基础模块、compileall、页面 JavaScript 语法、资源同步与发布清单检查均通过。
