# 短期会话路由

路由分别记录话题、承接消息、讲话对象与谈论对象，再供 Addressivity 和 Persona 判断是否参与。`topic_id` 表示讨论主题，DAG 的 `thread_id` 表示回复链，两者独立。

消息入图只建立平台引用与 mention 等确定性关系。路由在有限的近期候选中结合语义、时间、参与者与问答关系排序；模糊候选保存在 metadata，高可信推断才建立 `inferred_reply` 边。向量更新可以纠正推断，不重放已经处理过的回复。话题状态按 UMO 隔离，随会话 reset 清空。

收件人与引用独立：`@bot` 加引用群友时，群友是引用作者，bot 是提问对象。自然续聊需要当前对话者、时间和话题证据；其它用户随口说“真的假的”不自动获得同样待遇。机器人名字出现在第三人称陈述中只构成谈论对象，呼语与平台 @ 才是直接叫它的证据。

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| `conversation_router_enabled` | `true` | 开启短期路由 |
| `routing_neural_timeout` | `0.5` | 模糊消息最多等待向量的秒数，范围 0–2；0 不等待 |
| `neural_embedding_enabled` | `false` | 保留原默认；开启后使用配置的 AstrBot Embedding Provider |
| `embedding_cache_size` | `512` | 保留原向量缓存容量 |
| `strong_addressivity_threshold` | `0.70` | 保留原响应阈值 |

明确 @ 或引用走快速路径，不为向量阻塞。未启用神经向量、超时或服务失败时使用本地证据；不需要 FAISS 或外部向量数据库。检索窗口和排序阈值暂为模块常量，避免引入未校准的大量配置。

`node.metadata["routing"]` 保存话题、父消息、收件人、bot 是否为谈论对象及置信度和依据，进入消息语义上下文。分数是启发式证据强度，不是经过真实群聊校准的概率。没有足够线索的省略句可以保留未知，不强行归属。

本地回归通过后，可先在测试群使用现有 `shadow_mode` 查看预计行为，再逐步启用真实发送。生产群的准确率仍需用户授权提供的标注聊天 replay 验证；合成回归场景不代表真实群聊准确率。
