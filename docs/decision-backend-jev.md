# Jev 决策层（TypeSafe System One）

人设模式下「本轮要不要开口」的决策层：通过 AstrBot 原生 Provider 调用选中的 TypeSafe System One 模型（Jev），再把答案映射回插件自己的 `TurnDecision`。参与门闩、决策轨迹、Shadow 遥测与投递复用同一份决策契约。

## 职责

| 模块 | 职责 |
| --- | --- |
| `core/jev_decision.py` | 问什么（封闭词表）、答案怎么映射回 `TurnDecision`、置信度门槛在哪 |
| `core/decision_persona.py` | 提取身份、参与倾向和边界，构建专用决策人设摘要 |
| `core/reply_length.py` | 统一回复档位及完整代码、长文等例外，生成各层长度指引 |
| `core/systemone/provider.py` | AstrBot 原生模型服务，使用服务中的地址、密钥和模型 ID |
| `core/systemone/client.py` | HTTP 传输、端点与答案契约校验 |
| `core/systemone/routing.py` | 每轮解析选中的 Provider，模型或配置变化时作废旧结果 |
| `core/persona_engine.py` | 何时咨询决策层，拿不到答案时如何回落 |
| `core/context_retrieval.py` | 按引用、可信回复、话题和接收者检索历史，保留选择依据 |
| `core/dialogue_context.py` | 按参与者与话题冻结已发送回复、待回答问题及用户补充 |
| `core/topic_jev.py` | 冻结可见话题描述，构建封闭候选并校验话题提交 |
| `core/config.py` | 决策模型、提示词、超时和门槛的取值校验 |

## 一次调用回答什么

请求发送到选中模型服务的 `api_base` 与 `decision_path`（默认 `/v1/systemone`）组合出的地址，携带 `model`、`state` 与 `questions`。同次请求回答完整性、参与和回复样式的问题，按需追加对象、目标和话题判断：

| 问题 | 类型 | 选项（封闭词表） |
| --- | --- | --- |
| `completion` 是否说完 | choice | `complete` / `wait` |
| `join` 是否开口 | noul | 一个概率值（无置信度；仅普通群聊询问） |
| `action` 怎么回 | choice | `ignore` / `acknowledge` / `clarify` / `reply` / `close` |
| `state` 什么状态 | choice | `observing` / `casual` / `focused` / `supportive` / `playful` / `disengaging` |
| `length` 多长 | choice | `brief` / `normal` / `detailed` |
| `reason` 为什么 | choice | `addressed_request` / `addressed_question` / `ongoing_thread` / `open_group_topic` / `social_signal` / `other_recipient` / `boundary_or_sensitive` / `low_value_chatter` |
| `target` 回哪条 | choice | 本轮消息 ID（多于一条候选时才问） |
| `recipient` 实际对象 | choice | `bot` / `other` / `unclear`（引用、昵称或补充输入唤醒时才问） |
| `topic` 所属话题 | choice | 常规最多 8 个相关可见话题、`NEW` / `KEEP`；直接引用和已确认续聊强制保留 |

参与与回复样式分别处理：

- **词表是封闭的。** 每个问题只提供插件自己的选项，远程答案无法引入未知的动作、状态、长短或理由；答案按发出的选项键定位，不从散文里解析。回复目标只接受本轮消息；超过八条碎片时保留最新八个有效 ID，并按原顺序提供，保证最新消息可以被选择。背景消息不能成为回复目标。
- **普通群聊用动作与参与概率决定是否接话。** 动作置信度与 `jev_min_confidence` 比较，非忽略动作还需通过参与概率门槛；状态、长短和理由的低置信度不否决回复。它们低于同一门槛时分别采用默认状态（回复为 `focused`，收尾为 `disengaging`，旁听为 `observing`）、简短长度和不附加理由的行动目标。理由不确定时记录 `jev_action_accepted`，避免把一个不可靠的分类当作事实。
- **唤醒规则独立。** 真实 @机器人不调用 Jev；引用、昵称或补充输入唤醒省略未用于准入的 `join`，仍判断对象、完成度及回复样式，实际对象为机器人且对象置信度至少 0.35 才准入。获准唤醒后，低置信度动作默认回复，较弱的样式判断同样采用默认值。确认未说完且置信度达标时，仍先等待后续碎发。
- **判断题明确边界。** 任务请求与信息提问分别归类；解决任务和情绪支持按当前主要目的选择；确认、澄清、实质回复和收尾分别给出适用条件。当前消息及账号、引用关系先于人设出现在输入中，背景消息只作上下文，不能成为新的请求。
- **长回复按必要性选择。** `length` 默认优先 `brief` / `normal`，简单解释、短列表、少量步骤或技术问题本身不要求 `detailed`。只有当前用户明确要求详细展开，或紧凑回答会遗漏必要信息或步骤时才选 `detailed`；背景长度和复杂度不单独决定回复长度。`normal` 为 1~2 句或最多两项的短列表，回复 Agent 的普通群聊 `detailed` 要求全部段落合计不超过 120 字，并在发送前检查、压缩超长表达。仅要求详解不放宽限制，明确完整代码、长文或指定更长篇幅可展开。长度通过提示词控制，不在投递时按字数裁剪；这项偏好不改变参与概率与动作置信度门槛。

指令与判据用英语书写（模型自述最强语种），被判断的会话状态原样保留、不翻译；只有交给回复 Agent 的回应目标是中文，与插件其它回应计划一致。

## 群聊关系上下文

`snapshot_turn` 从消息 DAG 构建不可变决策上下文，回复 Agent 默认复用它。本轮 Jev 确认话题后，回复阶段会按照原始消息水位重新检索历史；原决策快照和回放记录保持不变，不额外调用决策模型，也不因刷新上下文改变已作出的静默或投递决定。诊断字段 `context_refreshed` 标记这次刷新。

- 优先保留平台引用和 @ 所指账号的消息；引用可跨越近期候选窗口，@ 选出的近期消息不等同于平台引用。
- 命中引用后沿 `fragment` 边补齐同轮、同作者的前置碎片；存在轮次序号时还校验先后顺序。碎片不消耗会话父链的八跳深度，但仍受祖先数量和背景预算限制；经过弱关联才选中的碎片保留该路径的不确定性，不会变成平台引用事实。
- 只有已建立的 `inferred_reply` 边才参与检索，置信度须达到路由记录的接受门槛（无记录时默认 0.72）；拒绝歧义、过期、与当前路由矛盾的边。候选父消息、旧 `semantic` 边不能直接充当回复事实。
- 用已确认且置信度达标的话题，取回其他成员的条件和补充，包括同话题中不同成员发给机器人的补充；用明确或高置信度接收者取回该账号的近期发言。共享机器人接收者本身不足以关联两个请求，已知不同话题及指向无关成员的旁支交谈会被过滤，即使旁支发言者也参与了本轮话题。
- 补充消息先经过话题和接收者过滤，再判断是否回复了已选问题；自动生成的 `mention` 边不能独自证明某条发言是对该问题的补充，也不能授权导入该发言的整个话题或其他成员回复分支。已确认当前话题时，不同话题的弱关联祖先会被排除。直接引用祖先仍按平台关系保留。
- 补充历史限制为过去 180 秒、最近 80 条候选；按本轮最后消息的位置和时间截断，排队期间后到的消息不会进入旧回合。最终背景最多 15 条、正文共 6000 字符，每条最多 1200 字符，选择后恢复时间顺序。
- 每条背景的 `context_evidence` 保存关系种类、依据消息 ID、置信度和依据码，按强度保留最多三条；较晚出现的平台引用不会被已有弱推断挤掉。`context_policy` 提醒模型区分引用事实与本地估计；同话题不代表同接收者，背景消息不能成为本轮回复目标。
- 每轮先去重字段、共享重复身份并清理空值，普通请求也执行；保留全部本轮消息 ID、账号、引用关系、约束正文、零值置信度和明确的真假标记。共享历史身份放在 `member_identities` 中；同账号不同时期的名字保留各自归属，同名不同账号不会合并。原始快照及回复模型上下文不被修改。
- 只有超预算后才裁正文；长消息保留开头和末尾条件，并同步碎片映射。先限制辅助观察与可选话题，再优先裁掉弱关联历史。至少保留最强的一条可信关联背景，包括未被引用的同话题或高置信度接收者补充。管理员指引在空间允许时完整保留，最后才按剩余空间压缩；学习快照仍保留原文和完整特征。
- 话题按查询词重合度和近期活动筛出常规最多 8 个，每个候选都有摘要；直接引用和已确认续聊的既有话题优先且强制保留，必要时超过 8 个，仍检查可见水位、过期状态及原对象有效性。强制候选不在预算压缩中移除；无法容纳时保守拒绝调用。
- 决策人设使用不增加模型调用的提取式摘要，最多 1200 字符，优先原文中的身份、参与倾向和边界句，覆盖角色卡中后部的相关内容。很长的同类条款仍受摘要预算限制；完整人设继续交给回复 Agent。
- 运行时状态严格限制为 12000 字符。必要身份、关系、保留背景及正文无法放入预算时记录 `jev_state_budget_exceeded`，不调用模型并保持静默。背景和话题候选共用 `TurnContext.visible_node_ids` 水位；话题标签、摘要和排序依据在入队前冻结。若话题含水位外的 DAG 源消息，即使其时间戳与本轮相同，也只用水位内摘要生成候选标签。等待期间的后到消息及标签变更不会进入旧请求。提交仍检查当前回合、路由、配置、话题对象和有效期。
- 话题确认后的刷新只更新消息的话题判断，保留快照中的发言者、引用者、@ 和平台引用原文。已捕获的引用链和仍属于确认话题、具有 `same_topic` 依据的条件，即使在等待期间被 DAG 清理，也会保留原始内容和身份；切换话题时移除不相关条件。原始快照与新增可见背景合并后统一按证据强度分配 15 条和 6000 字符预算。

## 决策数据与持续对话

长度规则在 `core/reply_length.py` 定义一次，生成 Jev 判据、默认中文回复提示词和回复系统指令。调整后运行 `python scripts/sync_prompt_defaults.py` 同步配置页的默认提示词与说明；发布检查会拒绝不同步的配置。管理员自定义提示词仍保留。

- `conversation.dialogue` 从已经发送的 Bot 节点投影，不创建第二套可变聊天记录。包含参与者、话题、最近双方消息 ID、已发送回复、待回答问题、交互状态、相对年龄、最多四条用户原文补充及来源 ID。Bot 回复摘录最多 800 字符，问题最多 240 字符，单条用户补充最多 600 字符；这些是有来源的摘录，不推测目标已完成或工具已执行。当前回合碎片不重复作为旧用户补充。
- 入队时冻结对话内容，使用原有消息水位排除后到消息。Jev 确认话题后的刷新只能选择原水位内的锚点；同一锚点保留原摘录，原锚点已被清理且话题仍匹配时保留已捕获的数据。明确不同话题时不沿用旧对话。
- 续聊按“参与者＋话题”查找成功投递锚点，A→B→A 不再依赖全群最后一条 Bot 回复；有效续聊不作为新主动开场消耗额度，并可通过群冷却入口及等待队列，仍需 Jev 的参与和动作判断。默认窗口 120 秒；同话题被独立确认且置信度至少 0.8 时，`focused` 任务为 900 秒，`supportive` 为 300 秒。收尾、已停止的成员旧锚点及明确其他接收者不获得续聊资格。成员停止代次随有效消息保存，普通新消息的修订不会作废既有对话。
- 待回答问题可来自一条 Bot 回复的前置碎片。接收者评分只排除已确认、置信度至少 0.8 的不同话题插话；未知、歧义及同话题插话仍保留原有惩罚，明确人类收件人仍优先。
- 当前碎片的 `text_spans` 是正文中的零基 `[start,end)` 区间，正文裁剪后同步更新；无法映射或被完全裁掉的碎片保留最多 64 字符原文摘录。背景 `age_seconds` 相对于本轮快照，不随排队增长。大量碎片下相同的状态字段通过 `fragment_defaults` 共享；每条的作者、引用、提及及接收者 ID 继续显式保留，最新碎片保留完整语义。
- 状态最多 12000 字符，完整请求另限 18000 字符，包含原生传输序列化后的问题说明、选项及模型名。构建阶段为模型名预留 256 字符，原生路由在发送前按实际模型名再次核对；话题删减后同步收紧选项及接受映射。保留完整性等待、补充输入、聚合时停顿、回合年龄、队列延迟和已用主动接话次数；先裁剪辅助观察与低相关话题，再缩短人设、对话摘录及正文。必要事实无法容纳时保持静默。
- 参与档位规则集中于 `participation_policy`，封闭问题只描述各自判断标准。默认回复指引要求推进未完成目标、保留最新约束与修正、避免重复操作，仅在缺失信息阻碍推进时追问。精确匹配上一版默认提示词的配置自动采用新默认，管理员自定义文本继续保留。原生回复 Agent 的历史与记忆钩子继续使用。

`test_dialogue_context.py` 覆盖交错投递、话题与收件人边界、停止及重启、问句碎片、压缩后的正文映射、时间与队列区分、默认提示词迁移和输入补充生命周期，纳入后端维护检查。离线检查验证逻辑与请求内容；真实模型的判断质量仍需 Jev 回放评估。

`tests/fixtures/conversation_context_replay.json` 覆盖多人插话、补充条件、强弱推断、人类接收者、切换话题、旁支交谈和过期历史。`test_context_retrieval.py` 和 `test_context_audit_regressions.py` 纳入后端检查；后者还覆盖弱祖先扩展、后到话题、同时间标题水位、冻结标签、引用及同话题条件清理、长引用碎片链、未引用条件的预算和多碎片投递。离线回放验证输入归属与证据边界，真实 Jev 的决策质量和置信度变化仍需连接模型评估。

## 凭据与端点

- 在 AstrBot 的模型服务中配置 System One 服务的 `api_base`、`key`、`model`，启用模型后在插件的 `decision_provider` 选中它。插件沿用该原生服务，不再读取独立的 `jev_base_url`、`jev_model` 或 `jev_api_key_env`。
- 原生服务密钥支持直接填写以及 `$ENV_NAME` / `${ENV_NAME}` 环境变量引用；环境变量缺失时拒绝调用。错误信息不携带凭据或响应正文。
- 地址只接受 http(s)，不能含账号密码、查询参数或片段；携带密钥的远程服务必须使用 HTTPS。端点通过 `decision_path`（默认 `/v1/systemone`）和模型列表的 `models_path`（默认 `/v1/models`）配置，已有 `/v1` 前缀不会重复拼接。
- 默认模型别名为 `jev-latest`，调过门槛后可在原生模型服务中固定具体版本；网关模型 ID 和端点按该服务的实际协议填写。

## 传输契约

- **违反契约的响应整体丢弃。** 选项不在发出的判据里、概率越界、缺置信度、类型不符——任何一处都拒绝整份响应（`invalid_answers`），绝不把可疑答案近似成决策；调用方视为「没有决策」，走本地保守计划。
- **不重试。** 决策有每轮截止时间，重试落在回合之后只是浪费；超时（`jev_timeout`，只包住这一次 HTTP 调用）与网络错误都记为一次失败并回落。
- **复用连接池。** 每个原生 Provider 延迟创建并复用 HTTP 会话，模型列表和决策请求共用连接池；超时、密钥和请求头逐请求取值，不保存服务端 Cookie。AstrBot 重载或卸载该 Provider、结束临时模型列表查询时关闭会话。插件自身不关闭由 AstrBot 管理的共享 Provider。连接复用已用本地 HTTP 测试验证；真实网关延迟和判断质量需实际回放测量。
- **重配置作废在途决策。** 变更插件配置、Provider 或模型选择后，旧身份对应的结果不会在新配置下生效。
- `noul` 答案只有概率、没有置信度；`choice` 返回 `choice`/`probabilities`/`confidence`。

## 证据与观测

- 每轮的类型化答案存进 `SessionRuntime.jev_decision`（`confidence` 为动作置信度，各项原始置信度分别保留），随 `model_diagnostic["jev"]` 进入决策诊断。
- 指标：`jev_decision`（咨询到决策）、`jev_unavailable`（无可用答案、回落本地计划）。
- 控制台：会话轨迹标注「Jev 决策 动作置信 x.xx」，直接读取动作字段，兼容旧记录的最弱项汇总值；互联诊断的「决策层」卡片显示模型、调用/失败次数、耗时与置信度门槛。

## 配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `decision_provider` | 空 | 在 AstrBot 模型服务中启用并选择 Jev / System One 模型 |
| `decision_timeout` | `8.0` | 整个决策阶段上限，包括等待全局名额（1~30 秒） |
| `decision_prompt` | 默认参与指引 | 管理员参与规则，最多 4000 字符；留空恢复默认 |
