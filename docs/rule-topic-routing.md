# 规则对象识别与多人讨论归属

## v1.17.0：可选 LLM 判断

新版归属链路中，`discussion_judgment_mode` 可选 `rerank`（默认）或 `llm`。
LLM 模式使用 `discussion_llm_provider` 普通聊天模型及 `discussion_llm_timeout`（默认 3 秒）；模型留空继承回复模型或当前会话聊天模型。每次最多读取此前 16 条、每条 400 字的同会话历史，最多 8 个讨论候选，不读取未来消息或停止版本失效的历史。

模型联合输出隐含对象和讨论归属，严格校验候选 ID、有限数值和 NONE/UNKNOWN；显式 @ 和引用不被模型覆盖。不确定或调用失败保留规则结果；低分新讨论只保留种子，后续证据形成主题。两种模式共用匹配分数门槛；模型分数不能当实测概率。历史讨论不因切换而重算；新消息按新模式处理。

普通群消息在参与决策前等待一次有界 LLM 判断，会增加延迟；真实 @、引用和私聊不等待。相同节点不重复判断；后台窗口继续处理未判断节点并独立归纳标题。模型、配置、历史或停止状态变化时拒绝旧返回。所有边界验证和发言决策仍独立生效。关闭 `topic_reranker_enabled` 则两种额外归属判断及标题调用均关闭；关闭 `rule_topic_routing_enabled` 恢复旧 Jev 归属路径。

## rc.44 调用优化

- 同一防抖回合内、同一发言者和对象、相邻且无新 @／引用／换题标记的碎发，在候选快照相同时合成一个查询。最多四条、总计 800 字、跨度八秒；消息 ID 和原文分别保留，归属结论记录完成这段输入时的确认时间。
- 纯应答词、纯表情和媒体占位不单独调用 rerank；短版本号、有内容的短句和需要上下文的追问不一概过滤。明确互动归属和原始上下文仍保留。
- rerank 缓存仅复用完整相同输入：群／会话、epoch、停止版本、模型实例与配置、正文和候选内容/ID。成功结果有效期 45 秒，最多 256 条／4 MiB；无作用域的探针不缓存。同请求并发共享，最后一个等待者取消才取消底层请求。服务失败按 2–30 秒退避，新绑定立即重置；没有每日调用配额。
- 原生 rerank 每个 provider 最多两条请求同时在途。排队、模型耗时、缓存命中和合并碎发分别计数，不能将合并数量直接等同于实际费用节省。
- 规则路由不等待 embedding，也不取消其他语义消费者所需的后台预热。
- 回复准备按 decision/reply/other 阶段记录各能力服务的实际耗时。只对同一回合、同一来源范围和相同完整参数的版本化读取进行短时复用；前后版本需一致，服务替换、配置／人格／回合或停止版本变化即失效。无版本契约时不复用，`recall_context` 不缓存完成结果，以免漏掉新记忆。该缓存最多 64 条／4 MiB、有效期十秒。

`overview.call_optimizations` 提供 rerank 与叙事读取的计数和有界耗时样本，不包含消息正文。LLM 主题归纳、正式回复模型及其推理配置均保持不变。

## rc.43 修正

rerank 的低分只表示“尚未匹配已有讨论”，不等于“确定有一个新主题”。单条具体发言先保留为待定种子，只有后续引用或足够明确的语义匹配才形成正式讨论；多条消息引用同一种子时归入同一段，并记录后续确认时间。

LLM 主题归纳已经恢复：`topic_reranker_provider` 是独立的聊天模型，可与 `discussion_reranker_provider` 的原生 rerank 同时使用。已形成且至少有两条可见消息的讨论进入批量归纳；优先给模型代表内容和近期发言，得到概括性名称，已有名称复用。标题输出不能修改消息归属。

加载时，只将 rc.42 中可证明从未获得后续支持的单条主题恢复待定；不删除消息，也不凭人数合并历史讨论。因淘汰只剩一条可见消息的成熟话题不作这项迁移。下文为对象规则和原有接口约定；其中“代表句直接作为最终标题”和“低分直接新建”的旧行为已由上述修正取代。

本版默认启用 `rule_topic_routing_enabled`。对象识别只使用明确 @、引用作者、直接称呼及有明确起点的短期续说／互回，不搜索或推断具体父消息。续说间隔 45 秒，原始起点最多持续 120 秒；第三人插话、身份缺失、多人指向冲突时停止继承。

对象未知不等于群发，也不等于新话题。Jev / OpenAI Decisions 继续负责是否发言、回复风格和长度等参与决策，不再收到额外的对象和话题归属问题。规则对象通过不可变的当前回合快照进入决策和回复上下文；推断不会改写原生 @／唤醒事件。

## 配置

- `discussion_reranker_provider`：AstrBot 原生 Rerank 服务 ID，必须显式选择。与旧的聊天模型标题服务 `topic_reranker_provider` 独立；不会自动选一个已启用模型。
- `discussion_rerank_threshold`：默认 0.65；`discussion_rerank_margin`：默认 0.10。它们是初始决策参数，不是概率，也未经真实 QQ 独立集校准。
- `topic_reranker_enabled`：是否启用讨论归属辅助。
- `topic_batch_interval`：默认 30 秒，后台按群处理。每次最多 32 条，待处理队列上限 128；超出部分维持未知。每条最多比较 8 段近期讨论，一次原生 rerank 请求，不为对象判断发起调用。

未配置、服务不可用、超时、非完整或非法分数均保留未知；不回退聊天模型或 Jev 猜归属。当前消息最多尝试一次重排序，避免后台循环请求；下一条新消息可重新提供证据。修改配置不会将先前已归属消息批量改写。

## 多人讨论

按消息记录归属，不按人建立互斥分组。ABC 谈显卡、CDE 谈聚餐时，C 的不同消息可以分别归入两段；共享 C 不合并讨论。明确引用可以提供讨论依据，单纯 @ 某人不意味着与对方所有发言同主题。

候选只取当前消息之前的本群内容。rerank 比较每段讨论的具体代表句和近期最多三条内容；分数接近时保留多个候选并暂不提交。当前实现允许成员参与多段讨论，单条消息只提交一个主讨论；同时关联多段的消息保留候选，不强行合并。

代表句从有具体内容的消息中选择，按不同参与者的连接支持及时间衰减排序，过滤泛用短句。同一人重复发言不会无限抬高中心权重。代表句只是上下文入口，不是模型生成的主题概括；隐藏消息正文时也隐藏代表原文。

句子层的支持来自原生引用或规则续说起点。重排序评分只支持整段讨论，不把一次主题匹配伪造为对某条具体消息的连接；缺少句子层支持时以近期具体内容作为代表。

## 生命周期与兼容

网络请求在会话锁之外执行，提交时复核会话 epoch、配置、成员停止版本、消息对象、候选内容及归属。取消、重置、停止和过期结果不能更新新会话。只清除旧的猜测父边，保留原生引用。

`rule_topic_routing_enabled=false` 恢复旧归属路径；旧聊天标题服务配置保留。不会修改其他插件的 rerank 绑定、记忆嵌入服务或发言策略阈值。切换后若希望清除旧讨论状态，使用已有会话重置操作。

本次候选版的验证包括合成规则/并发测试、插件调用链测试、原生 Rerank 接口契约测试和配置页面测试。接口契约测试使用服务替身；尚不能据此声称真实云端 rerank 质量或自然 QQ 对话效果已通过验证。
