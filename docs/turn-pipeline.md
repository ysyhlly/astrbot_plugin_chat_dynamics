# 回合流水线职责

`main.py` 保留 AstrBot 钩子注册、配置同步、会话注册表和对外兼容方法。准备、增强、参与准入及完成回合的计算位于 `core/turn_pipeline.py`，以显式 host 参数使用已有会话；不创建第二份状态、不增加第二条发送路径。

`core/native_delivery.py` 同时拥有原生发送 guard、事件上下文和发送完成后的记账/尾段生命周期。钩子顺序、filter/exclusive 行为、成功发送才记账的约束保持不变。

拆分时对 7 个回合函数及 1 个发送完成函数做了规范化 AST 比较：除 host 参数名称及相对导入路径外，函数体一致。随后使用原有生命周期、原生投递、路由增强及逐回合回放测试检查行为。没有双跑在线写入路径来比较。

## 状态提交

1. 锁内记录有效消息与观察。
2. Jev 路径从本地路由构建上下文，锁外在同一次请求中进行完整性、参与及话题归属判断。`core/topic_jev.py` 提供闭合的既有话题候选及 NEW／KEEP 选项，归属达到 0.8 置信度且回合、节点与路由快照仍有效时锁内提交；无需机器人接话也可归入话题。选择等待说完时不新建话题。
3. 锁内从不可变 ParticipationSnapshot 构建 TurnEvidence，原 ParticipationPolicy 直接消费它；准入决策定稿后冻结历史 Trace。沉默消息仍提交参与状态。
4. 发送结果由 OutcomeRecorder 补充；成功平台发送后才写入 Bot 发言与额度。

## 成员身份

成员身份从 AstrBot 的 `get_sender_id()` / `get_sender_name()` 获取，DAG 保留每条消息的昵称、平台及引用原作者；身份主键仍为平台账号。Jev 与回复上下文中的 `author_identity` / `speaker_identity` 同时提供昵称和账号，QQ（OneBot V11）账号额外标明 `qq`。QQ 官方平台的 OpenID 和其他平台 ID 不冒充 QQ 号。仅平台 @ 组件的 ID 进入确定的提及证据，纯文本昵称继续交给语义判断。宿主历史保存正文及成员归属，不保存参与计划；恢复运行快照后仍保留身份与真实 @ 证据。

## 延迟预算与观测

普通回复与戳一戳的原生 Agent 统一通过 `PersonaEngine.generate` 进入 `LLMAdapter.provider_budget`：同一宿主上下文按 Provider ID 共享预算，默认并发 4，回复采用高优先级。排队与原生 Agent 的整段生成分别计时；不会绕过预算直接调用桥接器，也不重复领取名额。普通回合由 `tool_agent_timeout` 包含决策、宿主锁、Provider 查询、预算等待、生成与发送；真实 @ 和戳一戳再受 `reply_timeout` 的较短限制。

`run_owned` 为每次调用登记成员与独立任务。成员停止只取消该成员的任务和排队项，群组队列工作任务继续运行，领取的名额在清理时归还。重置和卸载取消全部旧调用；正在调用的会话不会被空闲清理器淘汰。桥接器还追踪 SDK 的工具执行子任务，取消原生 Agent 时一并停止，执行凭据保留 `started` 状态，避免重新执行已可能产生效果的工具。已经完成的工具操作无法撤回。

历史以原生 Agent reset 后的真实用户请求确定边界，后续工具插入的图片评审消息不改写这个边界。当前请求保存带归属的用户正文，清除本轮未送达的 Assistant 正文，保留原生思考、工具调用与结果配对。工具支持位置参数及 `send(message=...)`；最终结果同时包含正文与媒体时保留完整消息链，正文不再重复分段发送。普通回复和戳一戳都在宿主会话锁内提交实际送达内容，取消尾段也保留已经发送的部分。

正文按空行划分自然段，不再要求达到 1200 字才分段；段内单个换行不拆分。`max_fragments` 对普通回复和戳一戳同样生效，超过上限合并尾段，设为 1 时合并为一条。原生回复优先使用同一自然段边界，单段正文继续沿用原有句子与长度节奏。代码、公式、列表、链接及媒体链保留整体结构；作息要求简短回应时合并正文而不截断。每条成功发送的消息分别记录 DAG、平台回复身份和成员归属，同一回合仅计一次开口；取消或发送失败后只提交已经送达的部分。

普通消息在最多 0.25 秒的聚合窗口后进入 Jev，同一次请求增加 `completion` 判断。选择 `complete` 后直接生成并发送首条回复，不叠加拟人化思考停顿；选择 `wait` 且置信度达到门槛时保留结果，收到新输入才合并重判。补充等待由 `pending_input_timeout` 控制，默认从首条消息计时 60 秒，新片段不延长这条总截止时间；到期清理并记录 `jev_incomplete_expired`，不调用模型。快速碎发合并上限与补充等待分别计时。停止、重置与卸载清理缓冲。已经等待生成名额的唤醒请求保留自身身份，避免被无关聊天替换。

`flushed_at` 固定实际聚合完成时刻，发言停顿与生成队列延迟分别进入 Jev，排队时间不被误计为用户沉默。决策输入中的对话摘录、正文分段、背景年龄共用入队水位；当前正文压缩后同步重映射分段位置。

每回合的归属复用 Jev 请求，不调用普通 LLM 复判。候选包含全部活跃标签，相关和近期的最多 8 个话题额外附带简短讨论证据；已确定为新讨论时创建话题，首次确认的无标签话题也会请求标签。明确平台 @ 仍直接回复；引用边及真实提及证据不会被语义归属改写。

`core/topic_batch.py` 从首条新消息开始计时，默认 30 秒，可通过 `topic_batch_interval` 设置为 5–300 秒。持续发言不重置本批计时；队列为空时不保留轮询任务。普通 LLM 一批只为最多 8 个待命名话题生成标签，每个话题取最多 3 条消息；超额的新标签排入后续窗口，完成后停止计时。已有标签缓存复用，无待命名话题时不调用。生成超时由 `topic_title_timeout` 控制，默认 10 秒。失败采用退避，每话题最多三次尝试，后续新消息才触发失败标签重试。

活跃标签的寿命与短上下文评分窗口分开：超过 3600 秒无人继续讨论才归档，匹配成功的人类消息续期，Bot 消息不续期；缓存标签在 DAG 淘汰后仍可参与 Jev 匹配。路由入口、Jev 请求入口和会话清理器都会检查过期，清理器在群安静时也运行。归档不参与匹配，也不通过本地相似度自动重开；会话在现有归档 TTL 内保留历史标签。活跃话题最多 80 项，超额归档最早项；归档最多 32 项，沿用 24 小时 TTL。

Jev、话题归属与标签的模型 I/O 发生在运行会话状态锁外。归属提交检查原路由快照、会话 epoch、成员版本及配置；标题检查话题与取样消息的身份、成员停止版本及配置。其他成员或同一成员继续发言不会让有效标题作废。停止会移除该成员待处理消息，重置和卸载取消任务；旧结果不能写回。持久化保存标签、命名请求和人类活跃时刻，按重启时的时钟偏移恢复；队列与任务不进入快照。

概览接口包含 `latency` 和 `provider_budget`：前者汇总当前保留回合的 prepare、embedding_wait、rerank_wait、enrichment、decision、first_send；后者报告 Provider lookup/queue/generation 的调用量及 P50/P95。历史快照不恢复进程专属计时起点。没有生产压测数据时，不将局部受控延迟实验描述为生产收益。
