# 消息图快照契约

本轮落实审计路线的 PR1，不调整路由阈值、参与策略或学习策略门槛。

## 关系与字段

- `routing_contract.EDGE_KINDS` 统一消息图写入和恢复接受的类型。
- `reply`、`mention`、`fragment`、`inferred_reply` 保留原类型；历史 `semantic` 保持可撤销推断的语义。
- 推断关系恢复后可以撤销和替换；已有明确回复边不能被其他关系覆盖。
- `quoted_author_id`（引用作者）和 `topic_source_text`（话题识别文本）进入元数据白名单，与现有字段采用相同的有界 JSON 编码。不保存任意运行时对象。

## 旧数据兼容

继续读取 version 1 快照。缺失边类型时，仅当 `reply_to_id` 明确指向该父消息才恢复为 `reply`。未知或无法判断的类型跳过并记录日志。

旧版本已经将推断写成 `reply`、且没有可辨认来源的数据，无法准确逆向修复；本次不会猜测其原类型。历史 `semantic` 不升级为平台事实。

## 大小与保留策略

以 `json.dumps(payload, ensure_ascii=False)` 默认分隔符产生的 UTF-8 字节数为预算口径，包含完整外层结构和诊断计数；这不是宿主存储文件的物理大小保证。

优先保留最近活跃会话。单个会话超限时，用二分搜索保留最新节点后缀；非节点数据仍无法容纳时丢弃该会话，继续尝试其他会话。固定全局诊断超限时清空可选的 metrics 和 shadow_decisions。连最小外层结构都无法容纳的预算会显式报错。

`dropped_nodes` 和 `dropped_sessions` 记录预算裁剪的数量，`truncated` 表示发生裁剪；原有每会话节点、话题、归档条数限制继续生效。裁剪只作用于导出副本。指向未保留节点的边在恢复时不会建立；平台引用仍使用原有迟到父消息机制。
