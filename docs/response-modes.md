# 自主回应方式

回复 Agent 在同一次生成中选择 `text`（纯文字）、`meme_only`（只发表情包）、
`text_meme`（表情包加文字）、`poke`（戳一下）或 `silent`（不说台词）。
群聊、@、引用和私聊均适用。戳戳仅在当前 QQ / NapCat 会话具备发送接口、
发言者和群号有效时提供，目标由程序固定为本轮发言者。
没有支持此协议的媒体插件时，仍可选择文字、状态旁白和可用的戳戳。无需新增配置或模型调用。

内部发送计划为 `{"reply_mode":"text","text":"要说的话","meme_id":null,"narration":""}`。
表情编号只能使用本轮已提供的候选。表情模式与文字是否为空必须匹配；
`poke` 要求文字和旁白为空、编号为空。`silent` 要求文字和编号为空，
`narration` 必须是一条非空第三人称状态旁白，单行且包括括号不超过120字。
程序统一使用全角括号，整条发送，不添加引用、不拆分、不转为语音。
只有当前回合因明确 @ 机器人而触发强制回应（`turn.mandatory_reply`）时才发送旁白。
普通聊天、主动接话、引用、昵称唤醒、戳戳和私聊中的 `silent` 均保持完全静默，
即使上游参与判断认为应该发言，也不发送“暂时没有回应”等状态提示。
这些回合的 `narration` 仍按现有模型协议解析，但不会发送或写入已交付聊天历史。
旁白依据当前角色、人设、作息和状态；没有依据时采用中性未回应描述，不能编造熟睡、忙碌等活动。
例如 `{"reply_mode":"silent","text":"","meme_id":null,"narration":"（安安暂时没有回应）"}`。
模型输出普通文字和旧版媒体计划仍可兼容。
代码、Markdown、用户要求的 JSON 放入 `text`，不能将发送计划本身交付给用户。

选择“不回”后的旁白与空响应、超时、协议错误分开记录。旁白和戳戳不会触发强制补台词或延迟表情；
发送成功后记录真实交付与历史，失败不会误记为已发送。
只有明确 @ 触发、到达回复 Agent 且选择此模式的回合才发送旁白；决策层跳过的普通群消息仍保持安静。
旧调用方的无旁白 `AgentOutput(reply_mode="silent")` 仍按完全静默处理。
模型选择方式前不提前交付首句，因此普通回复的首句时间可能比原来稍晚。

表情发送前失效时，图文模式只发送原先的文字，只发表情模式结束本轮。
发送失败和结果不确定仍遵循原有发送策略，不重试不确定的图片发送。
已有生成图片工具保留；调用发送或生图工具后不能再追加戳戳或不回旁白。

每个入站节点的 `reply_choice` 记录 `requested`、`actual`、`reason`、
`no_reply` 和 `delivered`，现有 `outcome` 继续记录最终发送状态。
旁白记录 `requested="silent"`、`actual="narration"`，戳戳记录 `actual="poke"`；
两者均有实际消息或动作，`no_reply=false`，`delivered` 仅在发送成功后为真。
非强制 @ 回合的旁白计划记录为 `requested="silent"`、`actual="silent"`、
`reason="narration_requires_at"`、`no_reply=true`、`delivered=false`。
`AgentOutput` 新字段均有默认值，兼容旧调用方。

本次旁白范围限制只更新 Chat Dynamics，保持已有 Visual Media 协议不变。单独更新
Chat Dynamics 时，旧版 Visual Media 仍支持旧表情计划；新回应协议只提供文字、旁白和可用的戳戳。
回滚使用部署前保存的同版本文件，候选不修改配置或数据库结构。
